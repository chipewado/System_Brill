# Phase B.1 — metric reconciliation audit

This checklist is intended to audit the earlier Phase B evaluation report before its metrics are used for decisions. It does not assume the earlier report's percentages are correct.

## Required inputs

- Raw annotation file with one row per sample.
- Raw prediction file generated by a named detector version.
- Stable sample ID and recording-session ID.
- Explicit class mapping and positive/negative definition.
- Dataset split manifest.

## Reconciliation checks

1. Rebuild the multiclass confusion matrix from raw labels and predictions.
2. Confirm that the sum of all matrix cells equals the number of evaluated samples.
3. Compute multiclass accuracy as diagonal sum divided by total samples.
4. Compute per-class precision, recall, and F1 using a documented zero-division policy.
5. Compute macro-F1 as the unweighted mean of class F1 values.
6. If reporting binary cue metrics, explicitly define positive classes and negative classes before collapsing the matrix.
7. Compute binary TP, FP, TN, FN from the collapsed labels.
8. Compute precision = TP / (TP + FP), recall = TP / (TP + FN), specificity = TN / (TN + FP), FPR = FP / (FP + TN), and accuracy = (TP + TN) / total.
9. Verify every displayed percentage against the underlying integer counts.
10. Ensure train/dev/test partitions are separated by recording session to prevent adjacent-frame leakage.

## Acceptance criteria

- A test fails if any published metric differs from recomputation beyond a defined rounding tolerance.
- Confusion-matrix totals equal the evaluated sample count.
- The report identifies the exact dataset and detector versions.
- Session-level split integrity is tested.
- False-positive examples are listed with source frame/session references.
- No metric is described as live-game performance unless evaluated on authorized, representative live-game data.
